Build a mobile-first MVP web app for a Korean tourism recommendation service.

Service name: GOAT
Full concept:
GOAT is a Gangwon-do tourism decision service that recommends domestic places with overseas-travel vibes.
The goal is not to show a long travel list.
The goal is to help the user decide where to go within 30 seconds by showing 3 recommendation cards.

Core service flow:
1. User selects a mood/reference card.
2. The selected mood is converted into scene tags.
3. The app matches those scene tags with the local GOAT place database.
4. The app shows 3 recommendation cards:
   - 장면 최적 카드
   - 같은 장면 대안 카드
   - 날씨 맞춤 대안 카드
5. The user can open KakaoMap, Naver Map, or Tmap.

Recommendation logic:
Internally, still use each place's:
- primary_mood
- mood_tags
- photo_point
- best_time
- best_season
- accessibility
- recommendation_use
- note

Scoring:
- +5 if the place name belongs to the selected mood category place list.
- +3 if primary_mood matches the selected mood category keywords.
- +2 for each matching mood_tag.
- +1 if recommendation_use matches the selected mood purpose.
- +1 if best_season is 사계절 or matches the selected/current season.
- +1 if accessibility contains 대중 상 or 자차 상.
- Penalize places with risk-related note keywords, but do not remove them automatically.
- Exclude data_status !== confirmed from the default result.

The 3 recommendation cards must have different roles:

1. 장면 최적 카드
- Highest scene/mood match score.
- Explain why it matches the selected mood.

2. 같은 장면 대안 카드
- Similar scene tag or mood category.
- Useful when the first place is crowded, risky, too far, or not suitable.

3. 날씨 맞춤 대안 카드
- Better for season, weather, accessibility, or indoor/outdoor suitability.
- Since real weather API is not connected yet, use best_time, best_season, place_type, and note as mock logic.
