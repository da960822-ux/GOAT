## 1. 내가 맡은 핵심 역할

DB·AI 추천 로직 담당자는 단순히 JSON을 넘기는 사람이 아니라 아래 기준을 책임진다.

1. **58개 장소 seed 데이터 유지**  
   `GOAT-001 ~ GOAT-058` 전체 후보를 삭제하지 않고 관리한다.

2. **43개 1차 추천 pool 기준 설명**  
   43개는 삭제본이 아니라, 일반 방문지 추천에서 쓰는 `PRIMARY43` 조건 pool이다.

3. **태그 표준화 기준 관리**  
   장면/무드/스타일/장소유형/활동/조건/의도/위험 태그를 구분한다.

4. **추천 로직 품질 검증**  
   테스트 케이스 13개가 기대 Top3를 반환하는지 확인한다.

5. **백엔드·프론트에 정확한 전달**  
   백엔드는 로직과 저장 필드, 프론트는 응답 타입과 카드 필드만 보면 되게 정리한다.

## 3. 장소 pool 기준

### 3-1. ALL58

`ALL58`은 전체 seed 후보 58개를 그대로 사용하는 pool이다.

사용 상황:

- 숙소/료칸/리조트/카라반 의도가 들어온 경우
- 해안도로, 주상절리, 잔도처럼 확장 후보가 필요한 경우
- future_candidate 또는 needs_verification 후보까지 비교해야 하는 경우
- PRIMARY43 결과가 약해서 adaptive retry가 필요한 경우

### 3-2. PRIMARY43

`PRIMARY43`은 58개 중 아래 기준을 만족하는 일반 방문지 중심 pool이다.

```txt
confirmed + 비숙박/비리조트
```

중요한 점:

- 43개는 “최종 DB”가 아니다.
- 58개에서 15개를 삭제하는 구조가 아니다.
- 요청 조건에 따라 계산 pool만 잠시 43개로 좁히는 것이다.
- 프론트 응답에서 `candidatePoolSize: 43`이 나와도 정상이다.

## 4. 태그 분류 기준

| 태그 그룹 | 의미 | 예시 | 추천 로직에서 하는 일 |
|---|---|---|---|
| `sceneTags` | 실제 보이는 장면 | 바다, 해안도로, 철길, 목장, 숲, 협곡 | 가장 강한 점수 기준 |
| `moodTags` | 추상 분위기 | 청량함, 이국적, 낭만적, 탁트임 | 직접 추천보다 moodExpansion으로 확장 |
| `styleTags` | 해외감성/연상 스타일 | 일본감성, 캘리포니아, 발리, 북유럽, 알프스 | 장면 태그와 결합될 때 강해짐 |
| `placeTypeTags` | 장소 유형 | 카페, 시장, 숙소, 목장, 정원 | 보조 점수/화면 분류 |
| `activityTags` | 사용 목적 | 드라이브, 산책, 서핑, 별보기, 카페투어 | 보조 점수/레퍼런스 카드 구성 |
| `conditionTags` | 계절·시간·날씨 | 봄, 겨울, 오전, 일몰, 흐린날 | season/time/weather 보정 |
| `intentTags` | 사용자의 방문 의도 | 숙소, 료칸, 리조트, 카라반 | ALL58 pool 전환 |
| `riskTags` | 주의 요소 | 차도, 파도, 절벽, 통제, 야간주의 | 안전 문구/감점/배지 |

### 핵심 판단

- `바다`, `해안도로`, `목장`, `철길`, `협곡`은 실제 장면이므로 강한 태그다.
- `청량함`, `이국적`, `낭만적`은 추상 무드라 단독 추천력이 약하다.
- `숙소`, `료칸`, `리조트`는 scene이 아니라 intent다. 그래서 pool 전환 기준으로 본다.
- `차도`, `파도`, `절벽`, `통제`는 추천 제외보다는 안전 안내와 감점에 쓴다.

## 5. 태그 확장 기준

추천엔진은 입력 태그를 그대로만 보지 않고, 아래 방식으로 확장한다.

### 5-1. aliases

같은 의미 또는 거의 같은 장면으로 보는 태그다.

예시:

```txt
바다 → 해변, 오션뷰, 해안, 수평선, 방파제
해안도로 → 로드트립, 드라이브, 바다도로, 헌화로
초원 → 들판, 목장, 양떼목장, 하늘목장
일본감성 → 일본, 일본풍, 일본소도시, 가마쿠라, 오노미치, 교토
```

### 5-2. relatedTags

같은 의미는 아니지만 함께 보면 좋은 연관 장면이다.

예시:

```txt
캘리포니아 → 해안도로, 로드트립, 서핑, 해변, 팜트리
알프스 → 목장, 초원, 고원, 설경, 유럽감성
북유럽 → 숲, 자작나무, 침엽수림, 겨울, 설경
몽골 → 고원, 별, 은하수, 초원
```

### 5-3. moodExpansion

추상 무드를 실제 장면/스타일 태그로 풀어주는 기준이다.

예시:

```txt
청량함 → 바다, 해변, 서핑, 고원, 호수, 숲, 라벤더
이국적 → 캘리포니아, 발리, 산토리니, 유럽감성, 일본감성, 북유럽, 알프스
탁트임 → 고원, 초원, 해안도로, 오션뷰, 전망대, 풍력발전기
감성적 → 카페, 골목, 소품샵, 서점, 일본감성, 레트로
```

## 6. 추천 점수에 실제로 영향을 주는 요소

추천 결과는 단순히 태그가 포함되어 있는지로만 정해지지 않는다.

| 요소 | 결과에 주는 영향 |
|---|---|
| 태그 직접 일치 | 가장 기본 점수. 장소 태그/장소명/포토포인트와 입력 태그 비교 |
| aliases | 유사어 일치 시 점수 부여 |
| relatedTags | 약한 확장 점수 부여 |
| moodExpansion | 추상 무드를 실제 장면 태그로 바꿔 후보 확보 |
| sceneSpecific 보정 | 해안도로/일본소도시/목장/협곡 등 대표 조합에서 특정 후보를 강하게 올림 |
| regionGroup 보정 | 사용자가 권역을 고르면 해당 권역 가산, 다른 권역 감점 |
| lodgingIntent 보정 | 숙소 의도면 숙소 후보 가산, 일반 방문지 감점 |
| season/time/weather 보정 | 선호 계절·시간·날씨가 맞으면 소폭 가산 |
| dataStatus 보정 | confirmed 가산, future_candidate 소폭 가산, needs_verification 감점 |
| adaptive ALL58 retry | PRIMARY43 결과가 약하면 58개 전체 후보로 재시도 |

그래서 추천 로직은 유의미하게 결과를 바꾼다. 실제 테스트에서도 바다/해안도로, 일본 소도시, 알프스 목장, 료칸 숙소, 협곡, 북유럽 숲 등 조합마다 서로 다른 Top3가 나온다.

## 8. 자유 태그 조합에 대한 판단

모든 가능한 자유 태그 조합을 보장하는 구조는 아니다.

예를 들어 아래 태그는 단독으로 쓰면 후보가 부족하거나 추천이 흔들릴 수 있다.

```txt
꽃밭, 폐광, 산, 호수, 발리, 산토리니,
이국적, 청량함, 낭만적, 탁트임, 도시적,
몽골, 아이슬란드, 프로방스, 오사카,
철길, 별보기, 드라이브, 트레킹,
카라반, 자쿠지, 풀빌라
```

프론트에 전달할 기준:

```txt
약한 태그는 단독 선택으로 열지 않는다.
반드시 강한 장면 태그와 묶어서 레퍼런스 카드로 제공한다.
```

좋은 조합 예시:

```txt
발리 + 서핑 + 해변
호수 + 반영 + SNS
폐광 + 레트로 + 흐린날
꽃밭 + 라벤더 + 정원
몽골 + 고원 + 별
산토리니 + 지중해 + 전망
```

## 11. 내가 마지막으로 확인한 결론

- 태그 기준은 유효하다.
- 태그를 장면/무드/스타일/의도/조건/위험으로 나눈 방식도 적절하다.
- 기준 레퍼런스 조합 13개는 모두 후보 3개 이상이 있다.
- 모든 자유 조합을 보장하지는 않으므로 프론트는 레퍼런스 카드 중심으로 가야 한다.
- 추천 로직은 pool 전환, moodExpansion, sceneSpecific 보정, region 보정, lodging 보정, adaptive retry 때문에 결과를 유의미하게 바꾼다.
- DB 담당자는 58개 전체 seed 유지와 태그 표준화, 테스트 케이스 결과 보장을 책임지면 된다.


## v1.3+ 점수 추천 로직 간단 보완

이번 보완으로 기존 태그/장면/권역/계절/시간/날씨/데이터상태 점수에 아래 선택 점수가 추가되었습니다. 새 입력값이 없으면 0점 처리되어 기존 추천 결과는 유지됩니다.

| 입력값 | 예시 | 반영 방식 |
|---|---|---|
| `companionType` | `혼자`, `연인`, `친구`, `가족` | 동행 유형에 맞는 장소 성격이면 가산, 맞지 않으면 소폭 감점 |
| `travelPurpose` | `사진 위주`, `산책`, `액티비티`, `휴식`, `먹거리` | 여행 목적과 장소 유형/태그/포토포인트가 맞으면 가산 |
| `transportType` | `자차`, `대중교통`, `도보` | 장소 접근성의 자차/대중 `상·중·하` 값을 점수화 |
| `weatherTag` | `맑은 날`, `비`, `흐린 날`, `강풍`, `눈` | 날씨에 따라 야외/실내/해안/산악/도로형 장소를 가산·감점 |

카드의 `scoreBreakdown`에는 `companion`, `travelPurpose`, `transport`, `weather`가 포함됩니다. 자세한 기준은 `docs/score_logic_update_simple_conditions_v1_3_plus.md`를 확인하면 됩니다.
