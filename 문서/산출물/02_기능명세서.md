# GOAT 기능명세서 v2.0

> 작성일: 2026-06-24 | 버전: 2.0 | 기준 플랫폼: iOS / Android (React Native Expo)

---

## 현재 기획에서 빠진/보완해야 할 요소

### 사용자 관점
- 비회원 vs 회원 분기 정책 전무 — 북마크 시 로그인 유도 흐름 미정의
- 회원가입/로그인 화면 명세 없음 (Supabase Auth 연동은 있으나 화면 플로우 없음)
- 온보딩·스플래시 화면 없음 (권한 요청 흐름 포함)
- Android 하드웨어 백키 정책 미정의

### 기능 관점
- `POST /api/analyze-image` API 명세서에 완전 누락 (request body, response schema 없음)
- `POST /api/recommend` vs `GET /api/recommendations` 메서드·경로 불일치
- 북마크 목록 화면 상세 명세 없음 (정렬, 삭제 UX)
- 공유 기능(장소 상세 → 카카오/링크 공유) 없음
- 추천 재시도(`다시 추천`) 로직 상세 없음

### 데이터 관점
- `scene_tags[]` 컬럼이 아키텍처에만 언급, ERD에 없음
- KTO `contentId` 컬럼 없음 — 상세 이미지·혼잡도 API 호출 불가
- recommendation_logs에서 비회원 → 회원 전환 시 연결 마이그레이션 없음

### 보안
- 이미지 업로드 MIME 타입·파일 크기 검증 정책 없음
- Rate limiting 정책 없음 (`/analyze-image`는 LLM 비용 발생)
- Supabase 북마크 직접 호출 시 user_id를 클라이언트 body에 포함하는 구조 → JWT 서버사이드 추출로 변경 필요

### UX
- 스켈레톤 로딩 명세 없음 (추천 카드·장소 상세·북마크 목록)
- Empty state 미정의 (북마크 0개, 추천 결과 0개)
- 오프라인 처리 없음
- 카메라/위치 권한 거부 처리 없음
- 사진 분석 confidence 낮을 때 fallback 없음

### 운영
- KTO API 장애 시 fallback 없음
- 에러 트래킹 도구 미지정
- LLM 모델 선택 기준·비용 제어 미정의

### 법적/정책
- 위치정보 수집 별도 동의 팝업 없음 (위치정보법 의무)
- 사진 업로드 개인정보 처리 동의 없음
- KTO 공공데이터 출처 표기 의무 위치 미정

## 1. 개요

| 항목 | 내용 |
|------|------|
| 앱명 | GOAT (Gangwon Of All Time) |
| 목적 | 감성(무드) 기반 강원도 여행지 3장 카드 추천 — 결정 피로 해소 |
| 타겟 사용자 | 20~30대, 강원도 즉흥 여행 희망자, "어디 갈지 모르겠다" 상태 |
| 플랫폼 | iOS 16+ / Android 10+ (React Native Expo) |
| 핵심 가치 | 무드 → 조건 → 3카드: 60초 안에 여행지 결정 |

---

## 2. 사용자 역할 및 권한

| 역할 | 정의 | 가능한 기능 |
|------|------|------------|
| 비회원 (Guest) | 로그인 없이 앱 사용 | 감성 선택, 사진 분석, 추천 조회, 장소 상세 조회 |
| 회원 (User) | Supabase Auth 로그인 완료 | 비회원 기능 전체 + 북마크 저장/삭제/목록 조회 |

> 비회원이 북마크를 시도하면 로그인 유도 바텀시트를 표시한다. 추천 기능 자체는 비회원도 전면 허용.

## 4. 상세 기능 설명

---

### F-01 | 스플래시 화면

- **우선순위**: 필수
- **설명**: 앱 실행 시 로고 노출, Supabase 세션 복원, 필수 데이터 프리페치
- **입력**: 없음
- **출력**: 세션 복원 성공 → 랜딩 or 이전 화면 / 실패 → 랜딩(비회원)

**정상 흐름**
1. 앱 실행 → GOAT 로고 + 배경 이미지 표시 (1.5초)
2. Supabase Auth 세션 토큰 확인 (비동기)
3. places 테이블 기본 목록 프리페치 (백그라운드)
4. 온보딩 미완료(첫 실행) → 온보딩 화면으로 이동
5. 온보딩 완료 → 랜딩 화면으로 이동

**예외 흐름**
- 네트워크 없음: 오프라인 배너 표시 후 캐시 데이터로 랜딩 진입 허용
- 세션 만료: 비회원 상태로 랜딩 진입 (로그인 강제 없음)

**UI/UX 노트**
- Expo SplashScreen API 사용, 데이터 프리페치 완료 전까지 splash 유지
- 최대 대기 3초 초과 시 강제 진입

---

### F-02 | 온보딩

- **우선순위**: 중요
- **설명**: 앱 최초 설치 후 1회만 표시. 핵심 기능 3단계 소개 + 위치정보 동의
- **입력**: AsyncStorage의 `onboarding_completed` 플래그
- **출력**: 온보딩 완료 플래그 저장 → 랜딩 이동

**정상 흐름**
1. 슬라이드 1 — "기분 따라 강원도 여행" (무드 선택 소개)
2. 슬라이드 2 — "내 사진으로 감성 찾기" (사진 분석 소개)
3. 슬라이드 3 — "3장의 카드로 결정 완료" (추천 카드 소개)
4. 위치정보 수집 동의 팝업 (선택 동의; 거부 시 거리 기능만 비활성)
5. "시작하기" 버튼 → 랜딩

**예외 흐름**
- 온보딩 도중 앱 종료 → 재실행 시 온보딩 1슬라이드부터 재표시
- "건너뛰기" 선택 시 위치 동의 없이 랜딩 진입 (이후 여행 조건에서 재요청)

**연관 기능**: F-15(권한 관리)

---

### F-03 | 랜딩 화면

- **우선순위**: 필수
- **설명**: 앱의 진입점. 두 가지 시작 경로 제공
- **입력**: 없음
- **출력**: 감성 선택 또는 사진 분석 화면으로 이동

**정상 흐름**
1. 강원도 배경 이미지 + GOAT 로고 표시
2. "기분으로 시작하기" → 감성 선택(F-05)
3. "내 사진으로 시작하기" → 사진 분석(F-06)

**예외 흐름**
- 없음 (정적 화면)

**UI/UX 노트**
- 배경 이미지 Blur + 오버레이로 텍스트 가독성 확보
- 하단 탭: 북마크(F-11), 앱 정보(F-14)

---

### F-04 | 인증 (회원가입 / 로그인)

- **우선순위**: 중요
- **설명**: Supabase Auth 기반 인증. 비회원도 핵심 기능 사용 가능; 북마크 시도 시 유도
- **입력**: 이메일+비밀번호 / 카카오 OAuth
- **출력**: JWT 토큰 발급, users 테이블 upsert

**정상 흐름 — 소셜 로그인 (카카오)**
1. 로그인 바텀시트 → "카카오로 계속하기" 버튼
2. Supabase Auth OAuth (카카오) 브라우저 열림
3. 카카오 동의 → JWT 반환
4. users 테이블 upsert (신규: INSERT, 기존: 세션만 갱신)
5. 바텀시트 닫힘, 이전 동작 계속 (예: 북마크 저장)

**정상 흐름 — 이메일**
1. 이메일·비밀번호 입력
2. 회원가입: 이메일 인증 메일 발송 → 인증 링크 클릭 → 로그인
3. 로그인: JWT 반환

**예외 흐름**
- 이메일 중복: "이미 가입된 이메일입니다" 토스트
- 이메일 미인증 상태 로그인 시도: "이메일 인증을 완료해주세요" + 재발송 버튼
- OAuth 취소: 바텀시트만 닫힘 (에러 아님)
- 네트워크 오류: "연결을 확인해주세요" 토스트

**연관 기능**: F-10(북마크 토글), F-11(북마크 목록)

**UI/UX 노트**
- 로그인은 별도 전용 화면 없이 바텀시트로 처리 (앱 흐름 유지)
- 비회원이 북마크 탭 접근 시 동일 바텀시트 표시

---

### F-05 | 감성 선택

- **우선순위**: 필수
- **설명**: 6가지 무드 카드 중 하나 선택. 여행 조건 입력의 전 단계
- **입력**: 무드 ID 선택
- **출력**: 선택된 moodId → 여행 조건 화면으로 전달

**무드 목록**

| ID | 감성명 | 대표 이미지 키워드 |
|----|--------|--------------------|
| serene | 잔잔하고 조용한 | 호수·안개·새벽 |
| majestic | 웅장하고 압도적인 | 설산·절벽·폭포 |
| romantic | 감성적이고 로맨틱한 | 노을·꽃·빛 |
| healing | 치유와 휴식 | 숲·온천·들판 |
| active | 활동적이고 신나는 | 해변·레포츠·캠핑 |
| nostalgic | 감성적이고 레트로한 | 시장·기찻길·골목 |

**정상 흐름**
1. 무드 카드 그리드 표시 (2열 3행)
2. 카드 탭 → 선택 상태 강조 + 햅틱 피드백
3. "다음" 버튼 활성화 → 여행 조건 입력(F-07)으로 이동

**예외 흐름**
- 선택 없이 다음 버튼 탭: 버튼 비활성 상태 유지 (또는 진동 피드백)

**연관 기능**: F-07(여행 조건), F-08(추천 결과)

**UI/UX 노트**
- 스텝 인디케이터: 1/3
- 카드 선택 애니메이션: scale(1.05) + border highlight

---

### F-06 | 사진 무드 분석

- **우선순위**: 필수
- **설명**: 사용자 갤러리 사진 → LLM Vision 분석 → 무드 자동 분류 → 여행 조건 입력으로 연결
- **입력**: 이미지 파일 (JPEG/PNG/HEIC, 최대 10MB)
- **출력**: `{ moodId, scene_tags[], mood_tags[], confidence }` → 감성 선택 결과로 사용

**정상 흐름**
1. "내 사진으로 시작" → 갤러리 권한 요청 (F-15)
2. 이미지 선택 → 미리보기 표시
3. "이 사진으로 분석" 버튼 → `POST /api/analyze-image` 호출
4. 로딩 화면 (분석 중 애니메이션, 최대 10초)
5. 결과: 감성 뱃지 + "이런 감성이 느껴져요" 문구
6. "다음" → 여행 조건 입력(F-07) (moodId 전달)

**예외 흐름**
- 갤러리 권한 거부: 안내 다이얼로그 → "설정에서 허용" 딥링크 + "기분으로 시작" 대체 버튼
- 파일 크기 초과 (>10MB): "10MB 이하 사진을 사용해주세요" 토스트
- 지원하지 않는 포맷: "JPEG·PNG·HEIC 파일만 지원해요" 토스트
- LLM 타임아웃 (10초): "분석에 실패했어요. 직접 감성을 선택할까요?" → F-05로 이동 옵션
- confidence < 0.6: "사진에서 감성을 특정하기 어려워요. 비슷한 감성들이에요" + 2개 무드 옵션 제시
- 분석 중 화면 이탈: 요청 취소 (AbortController), 다시 진입 시 초기 상태

**연관 기능**: F-05(감성 선택), F-07(여행 조건), F-15(권한 관리)

**UI/UX 노트**
- 분석 중: 로딩 스피너 + "AI가 사진 속 감성을 읽고 있어요" 텍스트
- 결과 표시: 감성 이름 + 관련 이모티브 키워드 3개 뱃지
- 사진은 서버에 저장하지 않음 (분석 후 즉시 폐기, 개인정보처리방침에 명시)

---

### F-07 | 여행 조건 입력

- **우선순위**: 필수
- **설명**: 동행·이동수단·방문 시간·목적·위치를 선택해 추천 정확도 향상
- **입력**: 앞 단계의 moodId + 4개 조건 + 위치
- **출력**: 추천 요청 파라미터 완성 → 추천 결과(F-08) 이동

**조건 옵션**

| 항목 | 옵션 | 필수 여부 |
|------|------|----------|
| 동행 | 혼자 / 연인 / 친구 / 가족 | 선택 |
| 이동수단 | 자차 / 대중교통 | 선택 |
| 방문 시간 | 오전 / 오후 / 일몰 / 저녁 / 밤·새벽 / 무관 | 선택 |
| 목적 | 가볍게 산책 / 사진 위주 / 액티비티 / 조용한 휴식 | 선택 |
| 위치 | 현재위치 / 지역 직접 선택 / 건너뛰기 | 선택 |

**정상 흐름**
1. 각 항목 토글 선택 (미선택 가능, "무관" 처리)
2. 위치 "현재위치" 선택 시 권한 요청 (F-15)
3. 위치 "지역 선택" 시 강원도 시·군 목록 드로어
4. "추천 받기" 버튼 → `POST /api/recommend` 호출 → 추천 결과(F-08)

**예외 흐름**
- 위치 권한 거부: 거리 표시 없이 진행 (추천 기능은 정상 동작)
- 네트워크 오류: 토스트 + 재시도 버튼

**연관 기능**: F-08(추천 결과), F-15(권한 관리)

**UI/UX 노트**
- 스텝 인디케이터: 2/3
- 조건 선택 여부와 무관하게 "추천 받기" 항상 활성 (moodId만 있으면 추천 가능)
- 위치 아이콘 + "내 주변 강원도 여행지 찾기" 설명 문구

### F-08 | 추천 결과

- **우선순위**: 필수
- **설명**: 3장의 카드를 역할별로 구분해 표시. 각 카드에 추천 이유 포함
- **입력**: moodId + 조건 파라미터 → `POST /api/recommend`
- **출력**: 추천 카드 3장 렌더링

**카드 역할 정의**

| 순서 | 역할 | 선정 기준 |
|------|------|----------|
| 1 | 장면 최적 | mood_tags 일치도 최고 점수 |
| 2 | 내 상황 맞춤 | 동행·이동수단·목적 일치도 최고 |
| 3 | 안전한 대안 | 혼잡도 낮음 + 접근성 우수 + 다른 지역 |

**점수 계산 로직** (데이터 담당 구현)
- `scoreMood()` — 감성 태그 일치도 × 가중치
- `scorePreferences()` — 동행/이동수단/목적 일치도
- `safetyScore()` — note 필드 위험 키워드 감점
- `distanceBoost()` — Haversine 거리 보정 (위치 제공 시)
- 동일 지역(city) 중복 방지: 3장 모두 다른 city 우선

**정상 흐름**
1. 로딩 (스켈레톤 카드 3장)
2. 카드 표시: 장소명 / 위치 / 추천 역할 뱃지 / 추천 이유 / 거리(위치 있을 때)
3. 카드 탭 → 장소 상세(F-09)
4. "다시 추천" → excludeIds에 현재 3개 추가 후 재호출
5. "처음으로" → 랜딩 화면으로 초기화

**예외 흐름**
- 조건 만족 장소 < 3개: 반환된 장소 수만큼 카드 표시 + "조건을 완화해서 더 찾아볼까요?" CTA
- 조건 만족 장소 0개: 에러 화면 + "조건 바꿔보기" 버튼 (F-07 재진입)
- "다시 추천" 시 전체 소진: "모든 강원도 명소를 다 보셨어요! 조건을 바꿔 더 탐색해보세요" + 조건 초기화 옵션
- API 에러: 에러 카드 + 재시도 버튼

**연관 기능**: F-07(여행 조건), F-09(장소 상세), F-10(북마크)

**UI/UX 노트**
- 스텝 인디케이터: 3/3
- 스켈레톤: 카드 높이 동일한 회색 블록 3개
- 로딩 문구: "강원도 어딘가가 당신을 기다리고 있어요..."
- 카드 진입 애니메이션: staggered fade-in (50ms 간격)

### F-09 | 장소 상세

- **우선순위**: 필수
- **설명**: 선택한 장소의 전체 정보. KTO API 실시간 데이터 포함
- **입력**: place_id → `GET /api/places/:id` + KTO API (contentId 기반)
- **출력**: 장소 전체 정보 화면

**표시 항목**

| 항목 | 데이터 출처 |
|------|------------|
| 대표 사진 (슬라이드) | KTO detailImage (places.kto_content_id) |
| 장소명 / 유형 / 주소 | places 테이블 |
| 무드 태그 뱃지 | places.mood_tags |
| 혼잡도 (요일별 그래프) | KTO visitAreaBasedList |
| 관광 설명 | places.description / KTO detailCommon |
| 최적 방문 시간·계절 | places.best_time / best_season |
| 주차 정보 | places.parking |
| 접근성 | places.accessibility |
| 유사 장소 3개 | `GET /api/places/:id/alternatives` |

**정상 흐름**
1. 진입 시 places 기본 정보 즉시 표시 (Supabase 데이터)
2. KTO 이미지·혼잡도 비동기 로드 (스켈레톤)
3. "카카오맵으로 길찾기" → 카카오맵 앱 딥링크 / 미설치 시 웹 브라우저
4. 북마크 아이콘 탭 → F-10
5. 공유 아이콘 탭 → F-13
6. 유사 장소 카드 탭 → 해당 장소 상세

**예외 흐름**
- KTO API 장애: 이미지 자리에 placeholder, 혼잡도 "정보를 불러오지 못했어요" 표시 (기본 정보는 정상 표시)
- place_id 없음 (잘못된 딥링크): "장소를 찾을 수 없어요" 에러 화면 + 뒤로가기
- 혼잡도 데이터 없는 장소: 해당 섹션 숨김 처리

**연관 기능**: F-10(북마크), F-12(유사 장소), F-13(공유)

**UI/UX 노트**
- KTO 이미지 스켈레톤: 16:9 비율 회색 블록
- 혼잡도 없는 장소: 섹션 자체 미표시 (빈 섹션 없음)
- 공공데이터 출처: 화면 하단 "관광 정보 제공: 한국관광공사" 문구 고정

## 6. 데이터 모델 개요 (보완)

### places 테이블 (추가 필요 컬럼)

```
kto_content_id  VARCHAR    -- KTO API detailImage·detailCommon 연동 키
scene_tags      TEXT[]     -- LLM 매칭용 장면 태그 (아키텍처 문서 명시 컬럼)
```

### 전체 관계도

```
users ─────────────┬──── bookmarks ──── places
                   │                     │
                   └──── recommendation_logs
```

### 주요 제약
- bookmarks: UNIQUE(user_id, place_id) — 중복 북마크 DB 레벨 방지
- recommendation_logs.user_id: ON DELETE SET NULL — 탈퇴 후 통계 보존
- places.data_status: 'confirmed' / 'needs_verification' — 데이터 품질 관리

## 7. 외부 연동

| 연동 대상 | 용도 | 비고 |
|----------|------|------|
| Supabase Auth | 회원 인증 (OAuth + 이메일) | 카카오 OAuth Provider 설정 필요 |
| Supabase REST | places·bookmarks·logs CRUD | RLS 적용 |
| Express API | 추천 로직, 사진 분석 중계 | `POST /api/recommend`, `POST /api/analyze-image` |
| LLM Vision | 사진 감성 분석 | Gemini 1.5 Flash 우선 (비용 절감); GPT-4o fallback |
| 한국관광공사(KTO) API | 장소 이미지·설명·혼잡도 | contentId 기반 호출; 서버 캐싱 필수 |
| 카카오맵 | 길찾기 딥링크 | 미설치 시 m.map.kakao.com 웹 fallback |
| React Native Share | 공유 기능 | 시스템 네이티브 공유 시트 |

### API 명세 보완 (기존 문서 불일치 수정)
