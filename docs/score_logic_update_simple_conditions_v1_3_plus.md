# GOAT 점수 추천 로직 보완 정리 — simple conditions v1.3+

## 1. 기존 점수 추천 방식

기존 `backend/recommendationEngine.ts`는 장소 58개 seed pool을 기준으로 아래 점수를 합산한 뒤, 화면 표시용 점수로 변환한다.

| 점수 항목 | 기존 역할 |
|---|---|
| `tag` | 사용자가 선택/분석한 태그와 장소의 `searchTags`, `moodTags`, `primaryMood`, `placeType`, `photoPoint` 등이 얼마나 맞는지 계산 |
| `sceneSpecific` | 해안도로, 일본 소도시, 알프스 목장, 협곡, 북유럽 숲 등 주요 장면별 보정 점수 |
| `region` | 사용자가 선택한 권역과 장소 권역이 맞으면 가산, 다르면 감점 |
| `lodgingIntent` | 숙소/료칸/리조트 의도가 있으면 숙소형 장소를 올리고 일반 방문지는 낮춤 |
| `season` | 선호 계절과 장소의 추천 계절이 맞으면 가산 |
| `time` | 선호 방문 시간과 장소의 추천 시간이 맞으면 가산 |
| `weather` | 기존에는 날씨 키워드가 장소 텍스트에 직접 들어있는 경우 중심으로 가산 |
| `dataStatus` | `confirmed`, `future_candidate`, `needs_verification` 상태에 따라 소폭 보정 |

기존 최종 계산 구조는 다음과 같았다.

```ts
rawScore = tag + sceneSpecific + region + lodgingIntent + season + time + weather + dataStatus
score = rawScore / 2.4 를 0~98 범위로 제한
```

## 2. 이번에 추가한 입력값

이번 보완은 복잡한 실시간 데이터 없이 프론트/백엔드가 바로 넘길 수 있는 선택값만 반영한다.

```ts
companionType?: "solo" | "couple" | "friends" | "family" | string | null;
travelPurpose?: "photo" | "walk" | "activity" | "healing" | "food" | string | string[] | null;
transportType?: "car" | "public" | "walk" | string | null;
weatherTag?: string | null;
```

한국어 값도 그대로 받을 수 있다.

예시:

```json
{
  "companionType": "연인",
  "travelPurpose": "사진 위주",
  "transportType": "자차",
  "weatherTag": "맑은 날"
}
```

## 3. 추가/수정한 점수 항목

| 새 점수 항목 | 판단 방식 | 점수 영향 |
|---|---|---|
| `companion` | 혼자/연인/친구/가족에 맞는 장소 성격인지 확인 | 약 -8 ~ +12 |
| `travelPurpose` | 사진, 산책, 액티비티, 휴식, 먹거리 목적에 맞는지 확인 | 약 -10 ~ +15 |
| `transport` | 자차/대중교통/도보와 장소 접근성 `상/중/하`가 맞는지 확인 | 약 -8 ~ +8 |
| `weather` | 기존보다 강화. 맑음/비/흐림/강풍/눈 조건에 따라 방문 적합도 가산·감점 | 약 -8 ~ +10 |

보완 후 최종 계산 구조는 다음과 같다.

```ts
rawScore = tag
  + sceneSpecific
  + region
  + lodgingIntent
  + season
  + time
  + weather
  + companion
  + travelPurpose
  + transport
  + dataStatus

score = rawScore / 2.4 를 0~98 범위로 제한
```

## 4. 쉽게 보는 기준

### 동행 유형 `companion`

| 입력 예시 | 올라가는 장소 예시 |
|---|---|
| 혼자/혼행 | 조용한 서점, 미술관, 숲길, 정원, 성당, 카페 |
| 연인/커플/데이트 | 일몰, 블루아워, 카페, 정원, 오션뷰, 전망, 산토리니, 료칸 |
| 친구 | 서핑, 시장, 야간, 먹거리, 카페거리, 로드트립, 포토존 |
| 가족 | 가족여행, 동물, 목장, 수목원, 정원, 테마파크 |

가족 입력에서 차도 촬영, 급경사, 야간, 절벽, 통제 요소가 보이면 소폭 감점한다.

### 여행 목적 `travelPurpose`

| 입력 예시 | 올라가는 장소 예시 |
|---|---|
| 사진 위주 | 사진스팟, 포토존, SNS, 전망, 오션뷰, 반영, 일몰/일출, 철길, 라벤더 |
| 산책/가볍게 걷기 | 산책로, 데크길, 골목산책, 숲길, 정원, 호수, 카페거리, 서점 |
| 액티비티 | 서핑, 스카이워크, 출렁다리, 케이블카, 트레킹, 목장, 동물, 협곡 |
| 휴식/조용함 | 조용함, 숲, 정원, 카페, 서점, 성당, 미술관, 호수, 료칸 |
| 먹거리/야간 | 시장, 먹거리, 항구, 밤거리, 해산물, 버스킹 |

### 이동수단 `transport`

| 입력 예시 | 판단 방식 |
|---|---|
| 자차 | `accessibility.car`가 상이면 가산, 하이면 감점 |
| 대중교통/뚜벅이 | `accessibility.publicTransport`가 상이면 가산, 하이면 감점 |
| 도보 | 대중교통 접근성과 산책/데크길/골목/시장/카페거리 성격을 같이 봄 |

### 방문 적합도 `weather`

| 날씨 입력 | 올라가는 장소 | 내려가는 장소 |
|---|---|---|
| 맑은 날 | 해변, 해안, 오션뷰, 고원, 목장, 숲, 정원, 호수, 전망 | 거의 없음 |
| 비/우천 | 미술관, 카페, 서점, 시장, 폐광, 산업유산 | 해변, 해안, 산, 고원, 목장, 서핑, 도로, 별/은하수, 일출/일몰 |
| 흐린 날 | 폐광, 산업유산, 미술관, 카페, 서점, 시장, 항구 | 별, 은하수, 일출, 일몰, 전망 중심 장소 |
| 강풍/바람 | 미술관, 카페, 서점, 시장 | 해변, 해안, 절벽, 데크, 고원, 풍력발전, 서핑 |
| 눈/겨울 | 설경, 설원, 눈꽃, 상고대, 스키, 북유럽, 자작나무 | 해안도로, 도로, 절벽, 데크 일부 주의 |

## 5. 카드 출력 변경

추천 카드의 `scoreBreakdown`에 아래 항목이 추가된다.

```json
{
  "companion": 5,
  "travelPurpose": 8,
  "transport": 6,
  "weather": 4
}
```

또한 카드 표시값도 조금 더 구체화했다.

| 카드 필드 | 변경 내용 |
|---|---|
| `weatherFit` | 기존 `보통` 고정에서 `날씨 적합도 좋음`, `날씨 적합도 보통 이상`, `날씨 주의 필요`, `보통`으로 표시 |
| `parkingInfo` | 기존 `확인 필요` 고정에서 자차 접근성 기준으로 `자차 접근성 좋음/보통/낮음/확인 필요` 표시 |

## 6. 검증 결과

기존 QA 테스트 13개는 모두 통과했다.

```text
Recommendation test result: 13 passed, 0 failed
```

즉, 새 입력값이 없을 때는 기존 추천 결과를 유지하고, 새 입력값이 들어올 때만 동행/목적/이동수단/날씨 점수가 추가로 반영된다.

## 7. 아직 일부러 넣지 않은 것

이번 수정에서는 구현 부담을 줄이기 위해 아래는 넣지 않았다.

| 항목 | 이유 |
|---|---|
| 카드 3개 역할별 별도 선발 | 단순 Top3보다 구조가 커져서 다음 단계로 분리 권장 |
| 동일 지역/유형 다양성 제한 | 점수 로직과 후처리 로직이 섞이므로 다음 단계로 분리 권장 |
| 실시간 혼잡도/주차 | API 연동과 데이터 확보가 필요해서 MVP 초기에는 고정 문구/접근성 기반으로 제한 |
| 현재 위치 기반 거리 점수 | 좌표와 위치 권한이 안정화된 뒤 추가 권장 |

## 8. 다음에 가볍게 추가하기 좋은 항목

복잡하지 않으면서 점수 추천 방식에 적당한 다음 후보는 아래 순서가 좋다.

1. `sameCityPenalty`: 카드 3개 후처리에서 같은 시군이 3개 나오면 3번째 후보만 교체
2. `missingDisplayDataPenalty`: 이미지/좌표/지도검색어가 없는 장소는 소폭 감점 또는 카드 노출 제한
3. `safetyPenalty`: 안전 주의 문구가 강하면 `CONDITION_FIT` 카드에서만 감점
4. `simpleCrowdLevel`: 주말/연휴 입력이 있으면 유명 해변·시장·테마파크만 소폭 감점

이 네 가지는 실시간 API 없이도 현재 seed 데이터 기준으로 구현 가능하다.
