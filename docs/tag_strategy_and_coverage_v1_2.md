# GOAT 태그 전략 및 후보 커버리지 점검 v1.2

## 1. 태그를 나눈 이유

기존에는 `sceneTags`, `moodTags`, `extractedTags`가 섞여 있어서 `숙소`, `청량함`, `바다`, `캘리포니아`가 비슷한 방식으로 점수 계산에 들어갔다. 이 경우 두 가지 문제가 생긴다.

1. `청량함`, `이국적`처럼 추상적인 무드가 실제 장소 태그와 직접 매칭되지 않아 fallback으로 빠질 수 있다.
2. `숙소`, `료칸`, `리조트` 같은 의도 태그가 장면 태그처럼 취급되어 일반 방문지 추천 pool과 충돌할 수 있다.

그래서 v1.2에서는 태그를 아래처럼 분리했다.

| 구분 | 역할 | 예시 | 처리 방식 |
|---|---|---|---|
| sceneTags | 실제 보이는 장면 | 바다, 해안도로, 철길, 목장, 숲, 협곡 | 강한 점수 |
| moodTags | 추상 분위기 | 청량함, 이국적, 낭만적, 탁트임 | moodExpansion 후 낮은 점수 |
| styleTags | 해외감성/연상 스타일 | 일본감성, 캘리포니아, 발리, 북유럽 | 중간 점수 |
| placeTypeTags | 장소 유형 | 카페, 시장, 항구, 숙소, 미술관 | 보조 점수 |
| activityTags | 여행 목적 | 드라이브, 산책, 서핑, 별보기 | 보조 점수 |
| conditionTags | 계절/시간/날씨 | 겨울, 일몰, 흐린날 | 보정 점수 |
| intentTags | pool 전환 | 숙소, 료칸, 리조트, 카라반 | ALL58 전환 |
| riskTags | 안전 안내 | 차도, 파도, 절벽, 통제 | 감점/주의 문구 |

## 2. 추상 무드 보완

추상 무드는 단독으로 후보를 만들지 않고 실제 장면 태그로 확장한다.

| 무드 | 확장 태그 |
|---|---|
| 이국적 | 캘리포니아, 발리, 산토리니, 유럽감성, 일본감성, 북유럽, 알프스 |
| 청량함 | 바다, 해변, 서핑, 고원, 호수, 숲, 라벤더 |
| 낭만적 | 일몰, 블루아워, 정원, 카페, 성당, 산토리니 |
| 탁트임 | 고원, 초원, 해안도로, 오션뷰, 전망대, 풍력발전기 |
| 자연친화 | 숲, 목장, 초원, 고원, 호수, 정원, 자작나무 |
| 도시적 | 시장, 야간, 카페거리, 구도심, 버스킹 |
| 감성적 | 카페, 골목, 소품샵, 서점, 일본감성, 레트로 |

## 4. 단독 사용을 피해야 하는 태그

58개 장소로 모든 태그 조합에 후보 3개를 보장할 수는 없다. 아래 태그는 단독 선택 카드로 쓰지 않는다.

| 약한 태그 | 단독 사용이 위험한 이유 | 권장 조합 |
|---|---|---|
| 꽃밭 | 직접 후보가 적음 | 꽃밭 + 라벤더 + 유럽감성 |
| 폐광 | GOAT-021 중심 | 폐광 + 산업유산 + 흐린날 |
| 산 | 후보가 산악/설경으로 좁음 | 산 + 설경 + 겨울 |
| 호수 | 호수 후보가 2개 중심 | 호수 + 반영 + SNS |
| 발리 | PRIMARY43에서는 후보가 제한적 | 발리 + 서핑 + 해변 |
| 산토리니 | 직접 후보가 적음 | 산토리니 + 전망 + 지중해 |
| 이국적 | 너무 추상적 | 이국적 + 바다/정원/일본감성 중 하나 |
| 청량함 | 너무 추상적 | 청량함 + 바다/숲/고원 중 하나 |
| 낭만적 | 너무 추상적 | 낭만적 + 일몰/정원/성당 중 하나 |
| 탁트임 | 너무 추상적 | 탁트임 + 고원/해안도로/전망대 중 하나 |
| 도시적 | 너무 추상적 | 도시적 + 시장/야간/카페거리 중 하나 |

## 5. 로직이 유의미하게 바뀌는 지점

v1.2 추천 로직은 다음 항목에서 실제 추천 결과를 바꾼다.

| 로직 | 영향 |
|---|---|
| pool 정책 | 일반 방문지는 PRIMARY43, 숙소/확장 장면은 ALL58로 전환 |
| moodExpansion | 청량함/이국적 같은 추상 무드를 실제 장면 태그로 연결 |
| sceneSpecific 보정 | 해안도로, 일본 소도시, 목장, 협곡, 북유럽 숲 등 장면별 대표 후보를 끌어올림 |
| regionGroup 보정 | 사용자가 지역권을 선택하면 해당 지역 후보를 우선 |
| lodgingIntent 보정 | 숙소 의도에서는 숙소/료칸 후보를 강하게 우선 |
| adaptive ALL58 retry | PRIMARY43 결과가 약하면 ALL58로 재시도 |
| fallback 그룹화 | 태그가 약할 때 무조건 기본 Top3가 아니라 입력 계열별 fallback 적용 |

## 6. 최종 QA 기준

`recommendation_test_cases.json` 기준 13개 케이스가 모두 통과해야 한다.

- 기존 핵심 데모 5개 케이스 유지
- 커버리지 확장 7개 케이스 추가
- 추상 무드만 들어온 adaptive retry 케이스 1개 추가

정상 기준은 다음과 같다.

- `seedPoolSize`는 항상 58
- `candidatePoolSize`는 43 또는 58
- `poolPolicy`는 기대값과 일치
- `adaptivePoolRetryUsed`는 추상 무드-only 케이스에서 true
- Top3 placeId가 기대값과 일치
