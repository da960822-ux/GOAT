# GOAT 출발지·연계 거리 최종 구현 기준

## 1. 확정 사용자 흐름

출발지 설정은 선택 항목이며, 위치 확인 실패 때문에 추천 전체가 중단되지 않는다.

1. **현재 위치 다시 시도**
2. **출발 지역·주소 직접 선택**
3. **출발지 없이 계속**

현재 위치 확인 실패 안내 문구는 아래 문장으로 고정한다.

> 현재 위치를 불러오지 못했어요. 우선 거리 정보 없이 추천해드릴게요.

현재 위치는 foreground 권한 승인 후 최대 10초 동안 요청한다. 최신 좌표 수신에 실패하면 최근 5분 이내의 마지막 위치를 한 번 확인한다. 그래도 좌표가 없으면 위 안내와 세 가지 대안을 노출한다.

## 2. 출발지 입력 종류

| 종류 | 처리 |
|---|---|
| 현재 위치 | Expo Location에서 위도·경도 수집 |
| 빠른 지역 선택 | 전국 17개 시·도를 동일한 광역 단위로 제공하고, 시·도 대표 위치 좌표 사용 |
| 주소·지역·역 이름 검색 | 백엔드가 Kakao Local API로 좌표 변환 |
| 출발지 없이 계속 | 거리 정보 없이 정상 추천 |

Kakao REST API 키는 모바일 앱에 넣지 않고 백엔드 환경변수로만 관리한다.

빠른 선택 목록은 아래와 같이 통일한다. 화면에는 짧은 명칭을 표시하고 내부에는 정식 행정구역명을 저장한다.

- 수도권: 서울, 인천, 경기
- 강원권: 강원
- 충청권: 대전, 세종, 충북, 충남
- 호남권: 광주, 전북, 전남
- 영남권: 부산, 대구, 울산, 경북, 경남
- 제주권: 제주

도 단위 빠른 선택은 도청 소재지의 대표 좌표를 사용한다. 시·도 전체의 정확한 출발점이 아니므로 화면에 `시·도 대표 위치를 기준으로 설정돼요. 정확한 출발지는 위 검색을 이용해 주세요.`라는 안내를 표시한다.

## 3. 카드별 거리 점수 원칙

### 카드 1 — 최적 장면 카드

- `primaryTheme`, `mood_tags`, `sceneTags`, 여행 목적, 이동수단 접근성, 계절 적합도로 선택한다.
- **사용자 출발지와의 거리는 점수에 반영하지 않는다.**
- **카드 간 연계 거리도 반영하지 않는다.**
- 출발지가 있으면 `출발지 → 카드 1` 이동거리·예상시간을 정보로만 보여준다.
- `scoreApplied: false`로 응답한다.

### 카드 2 — 같은 무드 대안 카드

- 카드 1과 같은 `primaryTheme` 후보를 우선한다.
- 카드 1과 동일 장소는 제외한다.
- 장면·장소 유형이 지나치게 비슷하면 중복 페널티를 적용한다.
- **출발지가 정상 설정된 경우에만** `카드 1 → 카드 2 후보`의 연계 거리 점수를 최대 10점 적용한다.

### 카드 3 — 조건 맞춤 카드

- 여행 목적, 계절, 이동수단 접근성이 좋은 후보를 우선한다.
- `primaryTheme`은 카드 1과 달라도 된다.
- 여행 목적이 설정된 경우 `purpose_tags` 일치 후보를 우선한다.
- **출발지가 정상 설정된 경우에만** `카드 1 → 카드 3 후보`의 연계 거리 점수를 최대 10점 적용한다.

## 4. 연계 거리 점수

### Kakao 자동차 길찾기 응답이 있는 경우

예상 이동시간을 가장 우선해서 점수를 계산한다.

| 카드 1에서 후보까지 예상시간 | 연계 거리 점수 |
|---:|---:|
| 10분 이하 | 10점 |
| 20분 이하 | 8점 |
| 30분 이하 | 6점 |
| 45분 이하 | 4점 |
| 60분 이하 | 2점 |
| 60분 초과 | 0점 |

### Kakao 길찾기 실패 또는 미설정 시

Haversine 직선거리로 fallback한다. 이는 추천 실패가 아니라 보조 계산이다.

| 카드 1에서 후보까지 직선거리 | fallback 점수 |
|---:|---:|
| 5km 이하 | 10점 |
| 10km 이하 | 8점 |
| 20km 이하 | 6점 |
| 40km 이하 | 4점 |
| 70km 이하 | 2점 |
| 70km 초과 | 0점 |

출발지를 건너뛰었거나 현재 위치 확인에 실패하면 카드 2·3의 연계 거리 점수도 0점으로 두고, 거리 정보 없이 추천을 계속한다. 장소 좌표가 일부 누락된 경우에도 해당 장소의 거리 점수만 0점 처리한다.

## 5. 실제 처리 파이프라인

```text
사용자 조건과 출발지 입력
→ 출발지가 정상 적용됐는지 확인
→ 카드 1을 감성·조건 점수만으로 먼저 확정
→ 출발지가 적용되고 자차를 선택한 경우 전체 후보를 Haversine으로 빠르게 압축(1차 기본 최대 8개)
→ 압축 후보를 Kakao 자동차 길찾기로 조회
→ 실제 예상시간과 도로거리로 카드 2·3 재산정
→ 재산정 뒤 최종 카드가 바뀌면 해당 카드만 보완 조회(카드 2·3 산정용 요청당 총 최대 12곳)
→ Kakao 실패 후보는 Haversine fallback
→ 카드 3개 응답
```

이 구조는 추천 한 번마다 전체 장소에 외부 API를 호출하지 않도록 호출량과 응답 지연을 제한한다. 출발지에서 카드 1까지의 정보가 필요한 경우에는 별도 1회 호출하며, 라우트 결과는 백엔드 메모리에서 10분 동안 캐시한다.

## 6. 점수 계산식

### 카드 1

```text
selectionScore = baseScore
```

출발지·연계 거리·노출·coverage 보정은 카드 1에 적용하지 않는다.

### 카드 2·3

```text
selectionScore
= baseScore
+ routeDistanceBonus
- duplicatePenalty
- exposurePenalty
+ coverageBoost
+ lowExposureBoost
```

`originDistanceBonus`는 항상 0이다. 출발지가 정상 적용된 경우에만 카드 1 이동정보를 보여주고 카드 2·3에 **카드 1 기준 연계 거리**를 반영한다. 출발지가 없거나 확인에 실패하면 세 카드 모두 거리 점수 0점이며 `routeInfo`도 반환하지 않는다.

## 7. 실패·fallback 처리

| 상황 | 서비스 처리 |
|---|---|
| 위치 권한 거부 | 안내 문구와 3가지 대안 표시, 선택하지 않고 진행하면 거리 점수 0점으로 추천 |
| 현재 좌표 수신 실패 | 마지막 위치 1회 확인 후 3가지 대안 표시, 거리 점수 없이 진행 가능 |
| 현재 위치 유형인데 좌표 누락 | HTTP 400이 아니라 `originStatus: UNAVAILABLE`로 정상 추천하며 모든 거리 점수는 0점 |
| 주소 검색 실패 | 입력 재확인 안내, 빠른 지역 선택·출발지 없이 계속 가능 |
| Kakao 길찾기 실패 | Haversine fallback, 추천 정상 완료 |
| 장소 좌표 누락 | 해당 장소의 거리 점수 0점, 추천 후보 자체는 유지 |
| Kakao API 키 미설정 | 출발지가 적용된 경우 Haversine fallback, 경고 코드 기록 |

잘못된 위도 범위나 문자열 좌표처럼 요청 형식 자체가 잘못된 경우에만 HTTP 400을 반환한다.

## 8. 주요 API 응답 필드

```json
{
  "originStatus": "APPLIED | SKIPPED | UNAVAILABLE",
  "originNotice": "현재 위치를 불러오지 못했어요. 우선 거리 정보 없이 추천해드릴게요.",
  "recommendations": [
    {
      "routeInfo": {
        "from": "ORIGIN | FIRST_CARD",
        "fromLabel": "출발지에서 | 1번 장소에서",
        "distanceKm": 18.4,
        "durationMin": 27,
        "source": "KAKAO_ROUTE | HAVERSINE",
        "estimated": false,
        "scoreApplied": false
      }
    }
  ]
}
```

- 카드 1: `from = ORIGIN`, `scoreApplied = false`
- 카드 2·3: 출발지가 적용된 경우 `from = FIRST_CARD`, `scoreApplied = true`
- 출발지 미설정·확인 실패: 세 카드 모두 `routeInfo` 없음, 거리 점수 0점

## 9. 환경변수

```env
# Kakao Local 주소/키워드 검색 및 Kakao Mobility 자동차 길찾기
KAKAO_REST_API_KEY=

# 별도로 관리할 때만 입력. 비어 있으면 KAKAO_REST_API_KEY 사용
KAKAO_MOBILITY_REST_API_KEY=

# 출발지 검색 및 추천 호출 보호
GEOCODE_RATE_LIMIT_MAX=20
KAKAO_ROUTE_CANDIDATE_LIMIT=8
```

## 10. 운영 전 점검

- Kakao Developers에서 REST API 키와 허용 도메인/플랫폼 설정 확인
- 서버 환경변수에만 키 저장하고 Git에는 올리지 않기
- Android/iOS 실제 기기에서 위치 허용·거부·GPS 꺼짐·타임아웃 테스트
- 서울·춘천·강릉 등 서로 다른 출발지로 카드 1 점수가 바뀌지 않는지 확인
- 카드 2·3의 `routeDistanceBonus`가 10·8·6·4·2·0 기준으로 계산되는지 확인
- 출발지 적용 후 Kakao 키 제거 또는 네트워크 차단 상태에서 Haversine fallback 확인
- 출발지 미설정·확인 실패 시 카드 2·3의 거리 점수와 `routeInfo`가 모두 없는지 확인
- 주소 검색 실패 후 빠른 선택과 출발지 없이 계속이 정상 동작하는지 확인
